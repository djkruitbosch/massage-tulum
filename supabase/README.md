# Supabase

Local development uses the Supabase CLI Docker stack. To run the full local environment including migrations, seed data, and pgTAP RLS tests, ensure Docker Desktop is running and then execute: `supabase start && supabase db reset && supabase test db`. The `supabase start` command boots a local Postgres + Auth + Storage stack; `supabase db reset` applies all migrations in `supabase/migrations/` and the seed in `supabase/seed.sql`; `supabase test db` runs all pgTAP test files in `supabase/tests/`. Local credentials (URL, anon key, service role key) are printed by `supabase start` and must be placed in `apps/api/.env.local` and `apps/web/.env.local` (both gitignored). Never commit secrets. See `docs/adr/0002-supabase-environment-strategy.md` for the full environment strategy and `docs/adr/0003-rls-baseline-conventions.md` for the RLS testing conventions.
